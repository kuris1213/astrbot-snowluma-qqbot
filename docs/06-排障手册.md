# 06 · 排障手册

> 先看 [README 的常见问题表](../README.md#常见问题完整版见-docs06)；这里按「现象 → 原因 → 处理」展开。
> 排查顺序永远是：**看端口 → 看日志 → 看配置 → 重启对应服务**。

## 0. 三分钟定位法

```powershell
# 1) 谁在监听
Get-NetTCPConnection -State Listen -LocalPort 6185,6199,5099,8010,9882,4100 |
  Select-Object LocalPort,OwningProcess

# 2) 三个核心服务是否活着
Invoke-WebRequest http://127.0.0.1:6185 -UseBasicParsing -TimeoutSec 3 | Select-Object StatusCode
Invoke-WebRequest http://127.0.0.1:5099 -UseBasicParsing -TimeoutSec 3 | Select-Object StatusCode
Invoke-RestMethod  http://127.0.0.1:8010/health

# 3) 最近错误
Select-String .\logs\astrbot.err.log -Pattern 'Error|Traceback' | Select-Object -Last 10
Select-String .\logs\snowluma.err.log -Pattern 'Error|error' | Select-Object -Last 10

# 4) 一键自检
.\deploy\verify.ps1
```

## 1. 机器人「能发消息、收不到消息」

### 现象

- 机器人能按主动消息发出去，但别人发消息它完全没反应；
- SnowLuma 日志里没有 `[Event] 私聊`、`MsgPush`；
- 重启 SnowLuma 只打印 `already has SnowLuma pipe; will reconnect`，修不好。

### 原因

SnowLuma 的 hook 是在 **QQ 进程启动时**注入的。如果先开 QQ、后开 SnowLuma，hook 没挂上，收消息通道就是断的；而发消息走的是另一条通道，所以表现为「能发不能收」。

### 处理

```powershell
# 停 SnowLuma（AstrBot 可以不动）
.\deploy\stop-all.ps1
# 重启 QQ（SnowLuma 保持关闭）
Get-Process QQ | Stop-Process -Force
# 先起 SnowLuma，等它就绪
.\deploy\start-snowluma.ps1
Start-Sleep 10
# 再起 QQ
.\deploy\start-all.ps1 -NoQQ   # 只起服务
# 手动打开 QQ 扫码
```

之后确认日志：

```powershell
Select-String .\logs\snowluma.out.log -Pattern '\[Hook\] login detected|\[Event\] 私聊' | Select-Object -Last 10
```

`start-all.ps1` 已经做了保护：SnowLuma 90 秒内没就绪就不启动 QQ，并且带命名互斥锁防止并发启动。

## 2. 主动消息不发

### 2.1 先确认是不是配置问题

```powershell
# 看目标会话是否为空
Get-Content .\astrbot\data\config\astrbot_plugin_proactive_chat_config.json |
  Select-String 'session_list' -Context 0,3
```

- `session_list` 为空 → 永不触发；
- `friend_settings.enable = false` → 关闭；
- 当前时间在 `quiet_hours`（默认 23~10 点）→ 不打扰。

### 2.2 电脑睡眠导致定时任务错过

Windows 笔记本用电池时可能 3 分钟就睡眠，APScheduler 错过触发点后默认丢弃。

**临时**：

```powershell
powercfg /change standby-timeout-ac 0
powercfg /change standby-timeout-dc 0
powercfg /change hibernate-timeout-ac 0
```

**补丁**（旧部署用过，本仓库未包含）：编辑

```text
astrbot\data\plugins\astrbot_plugin_proactive_chat\core\task_scheduler.py
```

把 `misfire_grace_time` 的值改大（例如 `86400` 秒），保存后重启 AstrBot。升级插件会覆盖，需要重打。

### 2.3 手动验证插件本身是好的

```powershell
$umo = [uri]::EscapeDataString('snowluma:FriendMessage:<主人QQ>')
Invoke-WebRequest "http://127.0.0.1:4100/api/jobs/$umo/trigger" -Method Post `
  -Body '{}' -ContentType 'application/json' -UseBasicParsing
```

收到消息 → 插件正常，问题在调度/睡眠；没收到 → 看 `logs\astrbot.out.log` 里该插件的报错。

## 3. AstrBot 面板登录不了

| 情况 | 处理 |
|---|---|
| 从没登录过 | 初始密码在日志里：`Select-String .\logs\astrbot.out.log -Pattern 'Initial password'` |
| 日志被清空了 | 停 AstrBot，编辑 `astrbot\data\cmd_config.json`，把 `dashboard.password`、`dashboard.pbkdf2_password` 置空，重启，会重新生成并打印 |
| 改过密码但忘了 | 同上（会丢当前密码，但不动其他数据） |
| 提示验证码 | `dashboard.auth_rate_limit` 防爆破，等 1 分钟再试 |
| 502 / 页面空白 | AstrBot 没起或端口不是 6185，见第 4 节 |

重置密码的完整流程：

```powershell
.\deploy\stop-all.ps1
# 用编辑器把 dashboard 下 password / pbkdf2_password / jwt_secret 改成 ""
.\deploy\start-astrbot.ps1
Select-String .\logs\astrbot.out.log -Pattern 'Initial password'
```

> 改 JSON 时保留 UTF-8 BOM；用 VS Code 右下角选 `UTF-8 with BOM` 保存。

## 4. 端口被占用 / 起不来

```powershell
Get-NetTCPConnection -State Listen -LocalPort 6185 |
  ForEach-Object { Get-Process -Id $_.OwningProcess | Select-Object Id,Name,Path }
```

| 端口 | 常见冲突 |
|---|---|
| 6185 | 上一个 AstrBot 没退干净 |
| 5099 | 两个 SnowLuma 实例 |
| 6199 | 旧 AstrBot 残留 |
| 8010 | 其他 embedding 服务 |
| 9882 | 其他 TTS |
| 4100 | 主动消息插件重复加载 |

处理：`stop-all.ps1` 会按端口杀；仍然占用就手动 `Stop-Process -Id <pid> -Force`。

**不要**同时开两个 SnowLuma（一个在 `C:\SnowLuma`，一个在别处），会导致重复回复、hook 冲突。

## 5. 重复回复 / 两个连接

### 现象

同一句话回两遍，或 SnowLuma 日志里两个 `[OneBot.WS-Client] [astrbot] connected`。

### 原因

1. 两个 SnowLuma 实例；
2. 两个 QQ 账号的 `onebot_<QQ>.json` 都启用了 `wsClients`；
3. AstrBot 里配了两个 `aiocqhttp` 平台条目。

### 处理

```powershell
Get-Process node | Select-Object Id,Path
Get-NetTCPConnection -State Established -LocalPort 6199
```

- 只保留一个 `node.exe`（路径在 `C:\SnowLuma`）；
- 非机器人账号的 `onebot_<QQ>.json` 里 `wsClients[0].enabled = false`；
- `cmd_config.json` 的 `platform` 数组只留一条。

## 6. 语音相关

| 现象 | 原因 | 处理 |
|---|---|---|
| 发语音没反应 | `:9882` 没起 | `.\deploy\start-tts.ps1`，看 `logs\tts.err.log` |
| 每条都等很久才回 | CPU 跑 TTS，长句慢 | `ja_voice.probability` 降到 0.2；或换 TensorRT |
| 双份语音 | AstrBot 自带 TTS 也开了 | `provider_tts_settings.enable = false` |
| 语音是日语但很生硬 | `language: ja` 的翻译质量 | 改 `zh` 直接读中文，或换 `voice_profile` |
| 报 `model package invalid` | 模型缺文件 / shared 路径错 | 跑 `install-tts-model.ps1 -Verify`；检查 `TtsSharedDir` |
| 报 CUDA/TensorRT 错 | 引擎与显卡不匹配 | 删 `engines\` 用 ONNX，或 `aniflive-tts rebuild-engines` |

## 7. 知识库 / 向量检索

| 报错 | 原因 | 处理 |
|---|---|---|
| `Connection refused :8010` | 向量服务没起 | `start-embedding.ps1` |
| `torch not found` | `.venv-embedding` 没建好 | 重跑 `install.ps1` |
| `dimension mismatch` | 换了模型没重建索引 | 改 `embedding_dimensions` 并重建知识库 |
| 上传文档很慢 | CPU 推理 + 大批量切块 | 正常，分批上传 |
| 检索结果不相关 | 切块太大/太小 | WebUI 知识库设置里调 chunk size / overlap |

验证服务：

```powershell
Invoke-RestMethod http://127.0.0.1:8010/health
Invoke-RestMethod http://127.0.0.1:8010/v1/embeddings -Method Post `
  -ContentType 'application/json' -Body '{"input":"命运石之门"}' |
  Select-Object -ExpandProperty data | Select-Object -ExpandProperty embedding |
  Measure-Object | Select-Object Count
# Count 应该是 512
```

## 10. 编码 / BOM / 路径

### 10.1 脚本报「字符串缺少终止符」

`.ps1` 丢了 UTF-8 BOM。PowerShell 5.1 会把无 BOM 的 UTF-8 当 GBK 解析，中文字节破坏了引号配对。

修复：用 VS Code 另存为 `UTF-8 with BOM`；或：

```powershell
$p = '.\deploy\start-all.ps1'
$text = [System.IO.File]::ReadAllText($p, [System.Text.Encoding]::UTF8)
[System.IO.File]::WriteAllText($p, $text, (New-Object System.Text.UTF8Encoding($true)))
```

### 10.2 开机自启静默失效

- `startup-hidden.vbs` 必须**无 BOM**、纯 ASCII；
- `.bat` 必须**纯 ASCII**（中文注释会吞换行）；
- 路径含中文/空格时，VBS 里的引号要成对。

重新生成：重跑 `install.ps1`（会覆盖这两个文件）。

### 10.3 配置中文乱码

`cmd_config.json` / 插件配置应是 UTF-8 BOM。被记事本存成 ANSI 会乱码，重新用 `install.ps1 -Force` 渲染即可。

## 11. SnowLuma 注入失败

日志关键字：

```text
Node integrity: Low
hook failed
inject ... denied
```

原因与处理：

1. SnowLuma 放在带「低完整性标签」的目录（某些沙箱、下载目录、同步盘）→ 移到 `C:\SnowLuma`；
2. 没有管理员权限 → 用管理员身份启动一次，或把 SnowLuma 加到杀软白名单；
3. QQ 是 Microsoft Store 版 → 换官网 NT 版；
4. 杀软拦了 `native\*.dll` → 加白名单后重启 QQ。

## 12. 数据库锁 / 数据损坏

现象：AstrBot 启动报 `database is locked`，或人格/会话丢失。

```powershell
# 停服务后再动数据库
.\deploy\stop-all.ps1
Copy-Item astrbot\data\data_v4.db astrbot\data\data_v4.db.bak -Force
# 用 sqlite3 检查
sqlite3 astrbot\data\data_v4.db "PRAGMA integrity_check;"
```

- WAL 文件（`data_v4.db-wal`）不要单独删，先正常停服务，AstrBot 会自己合并；
- 真要修复：`sqlite3 data_v4.db ".recover" | sqlite3 new.db`，再替换。

## 13. 网络 / API 报错

| 报错 | 处理 |
|---|---|
| `401 Unauthorized`（DeepSeek） | Key 错/过期；WebUI → 服务商 → 改 Key |
| `402 Insufficient Balance` | 充值 |
| `timeout` | 配代理：`cmd_config.json` 的 `http_proxy`，或系统代理 |
| `SSL certificate verify failed` | 公司网络中间人证书；换网络或配 `REQUESTS_CA_BUNDLE` |
| SnowLuma 一直重连 | 令牌不一致 / AstrBot 没起 / 被防火墙拦回环 |

## 14. 完全重置

保留数据：

```powershell
.\deploy\stop-all.ps1 -IncludeQQ
.\deploy\install.ps1 -Force
.\deploy\start-all.ps1
```

彻底重来（**会丢人格和聊天记录**）：

```powershell
.\deploy\stop-all.ps1 -IncludeQQ
Remove-Item astrbot\data -Recurse -Force
Remove-Item .venv-embedding -Recurse -Force -ErrorAction SilentlyContinue
.\deploy\install.ps1 -Force
```
