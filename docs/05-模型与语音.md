# 05 · 模型与语音

本项目有两个「本地模型」，性质完全不同：

| 模型 | 用途 | 大小 | 是否随仓库 | 授权 |
|---|---|---|---|---|
| `bge-small-zh-v1.5` | 知识库向量化（512 维） | 92 MB | ✅ 在 `models\bge-small-zh-v1.5` | MIT（BAAI） |
| `kurisu-v2proplus` | 本地日语语音合成 | **7.0 GB** | ❌ 需自己安装 | 模型/音色需自行确认；AnifLive-TTS 本体是非商业授权 |

## 1. 本地向量模型 · bge-small-zh-v1.5

### 1.1 它解决什么

AstrBot 的知识库要把文本切成块、转成向量、存进 FAISS。默认可以调远程 embedding API，本项目改成本地服务，好处是：

- 不花 API 钱、不把知识库内容发给第三方；
- 断网也能检索；
- 512 维小模型，CPU 上 1 万条文档也能秒级检索。

### 1.2 文件

```text
models\bge-small-zh-v1.5\
├─ config.json
├─ model.safetensors         # 91.4 MB
├─ tokenizer.json
├─ tokenizer_config.json
├─ vocab.txt
├─ modules.json
└─ 1_Pooling\config.json
```

来自 <https://huggingface.co/BAAI/bge-small-zh-v1.5>（MIT）。仓库里这份是原样拷贝，没有改。

### 1.3 运行环境

`install.ps1` 会创建 `.venv-embedding`：

```powershell
uv venv .venv-embedding --python 3.12
uv pip install --python .venv-embedding\Scripts\python.exe `
  --index-url https://download.pytorch.org/whl/cpu torch
uv pip install --python .venv-embedding\Scripts\python.exe transformers
```

装完约 1.5~2.5 GB（torch CPU 版）。国内网络慢可以给 uv 配镜像：

```powershell
$env:UV_DEFAULT_INDEX = 'https://mirrors.aliyun.com/pypi/simple/'
```

> torch 一定要装 **CPU 版**。默认 PyPI 的 torch 会拖 CUDA 依赖，多出 2 GB 且用不上。

### 1.4 启动与配置

```powershell
.\deploy\start-embedding.ps1
```

- 服务：`deploy\tools\embedding_server.py`，OpenAI 兼容；
- 端口：`127.0.0.1:8010`；
- 模型目录：`deploy\config.psd1` 的 `EmbeddingModelDir`；
- AstrBot 侧：`provider_sources[local_bge].embedding_api_base = http://127.0.0.1:8010/v1`，`embedding_dimensions = 512`。

验证：

```powershell
Invoke-RestMethod http://127.0.0.1:8010/health
# {"status":"ok","model":"bge-small-zh-v1.5","ready":true}

Invoke-RestMethod http://127.0.0.1:8010/v1/embeddings -Method Post `
  -ContentType 'application/json' -Body '{"input":"测试"}'
# data[0].embedding 长度应为 512
```

### 1.5 重新下载（文件损坏时）

```powershell
uvx --from huggingface_hub hf download BAAI/bge-small-zh-v1.5 `
  --local-dir models\bge-small-zh-v1.5
```

国内可用镜像：`$env:HF_ENDPOINT='https://hf-mirror.com'`。

### 1.6 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `Connection refused :8010` | 向量服务没起 | `start-embedding.ps1` |
| `ModuleNotFoundError: torch` | venv 没装好 | 重跑 `install.ps1`（别加 `-SkipEmbedding`） |
| 维度不匹配 | 换了模型但没重建索引 | 改 `embedding_dimensions` 并重建知识库 |
| 内存占用高 | 默认线程数 = min(8, CPU) | 服务里改 `torch.set_num_threads` |

## 2. 本地日语语音 · AnifLive-TTS + kurisu-v2proplus

### 2.1 为什么不在仓库里

三个硬约束，不是偷懒：

1. **GitHub 单文件上限 100 MB**，模型里最大的 `bert.engine` 有 577 MB；普通 Git 仓库推荐总量 < 1 GB，模型 7 GB 会被拒。
2. **Git LFS 免费额度 1 GB**，7 GB 需要付费流量包，且 clone 极慢。
3. **授权**：AnifLive-TTS 是 PolyForm Noncommercial 1.0.0；模型是基于角色的音色包，公开再分发涉及角色版权。仓库只放安装脚本 + 校验，模型由你自己获取。

### 2.2 模型包里有什么

```text
kurisu-v2proplus\
├─ manifest.json                 # 模型元数据（id / 语言 / 精度 / 引擎指纹）
├─ source.json                   # 原始 GPT / SoVITS checkpoint 的 sha256
├─ checksums.json                # 每个文件的 sha256
├─ onnx\                         # 构建 TensorRT 引擎用的中间产物（约 2.0 GiB）
│  ├─ bert.onnx                  # 571 MB
│  ├─ ssl.onnx                   # 360 MB
│  ├─ gpt_encoder.onnx           # 304 MB
│  ├─ gpt_step.onnx              # 300 MB
│  ├─ sovits.onnx / sovits_stream.onnx
│  ├─ sv_embedding.onnx
│  └─ config.json
├─ engines\<fingerprint>\        # TensorRT 引擎：绑定 GPU/CUDA/TRT/平台指纹，换机器必须重建
├─ voices\default\               # 音色配置与参考音频
└─ validation-inputs\
```

**6.9 GiB 主要花在**：两套 TensorRT engine（各约 2.08 GiB，其中一套是旧指纹）+ ONNX（1.99 GiB）；`shared`（1.02 GiB，BERT/SSL 公共权重）在模型目录**之外**。

> **重要：AnifLive-TTS 只有 TensorRT-11 后端，没有 CPU 推理路径。**
> `onnx\` 是「构建引擎的原料」，真正跑推理的是 `engines\<fingerprint>\` 里的 `.engine`。
> 指纹包含 GPU 型号、显存、SM 数、CUDA/TensorRT 版本、操作系统——**换一台机器就不匹配，必须重建**：

```powershell
aniflive-tts model rebuild-engines --model-package <模型目录>
```

> 重建需要 NVIDIA 显卡 + CUDA + TensorRT 11，通常 10~30 分钟，产物约 2 GiB。
> 没有 NVIDIA 显卡就别装本地语音，改用其它 TTS 服务或让 `ja_voice` 保持关闭。

> `shared` 目录是 AnifLive 的公共权重，放在模型目录上一级，通过 `--shared-dir` 指定；
> 它不在模型目录里，分享模型时要一起带上（1.02 GiB）。

仓库里的 `models\tts\kurisu-v2proplus.metadata\` 保存了这个模型包的 `manifest.json`、`source.json`、
`checksums.json`（**只有元数据，没有权重**）。`install-tts-model.ps1 -Verify` 会优先用模型包自带的
`checksums.json`，没有就回退到仓库里这份，所以你可以拿它校验从别处拷来的模型是否完整。

### 2.3 安装 AnifLive-TTS

上游：<https://github.com/Hiruynk/AnifLive-TTS>，中文文档在 `docs\INSTALLATION_ZH_CN.md`。

要点（以你拿到的版本为准）：

```powershell
git clone https://github.com/Hiruynk/AnifLive-TTS C:\AnifLive-TTS
cd C:\AnifLive-TTS

# 需要 Python 3.10~3.12 + Rust 工具链（原生模块是 PyO3 编译的）
uv sync
# 或按上游文档：uv sync --extra runtime

# 确认命令可用
uv run aniflive-tts --help
```

装好后可执行文件通常在 `C:\AnifLive-TTS\.venv\Scripts\aniflive-tts.exe`。

### 2.4 放置模型

```powershell
# 从夸克网盘下载 2.31 GiB 的 7z（推荐，链接见下），然后指向本地文件
.\scripts\install-tts-model.ps1 -Source "D:\downloads\kurisu-v2proplus-portable.7z"

# 模型在你本机别处（目录联接，不占额外空间）
.\scripts\install-tts-model.ps1 -Source "D:\models\kurisu-v2proplus"

# 有直链时也可以直接下（.zip / .7z / 分卷 .001）
.\scripts\install-tts-model.ps1 -DownloadUrl "https://example.com/kurisu-v2proplus-portable.7z"

# 校验完整性
.\scripts\install-tts-model.ps1 -Source "D:\models\kurisu-v2proplus" -Verify
```

夸克网盘（当前分发位置）：

| 项 | 值 |
|---|---|
| 链接 | <https://pan.quark.cn/s/32fa2c35348a?pwd=RF3D> |
| 提取码 | `RF3D` |
| 文件 | `kurisu-v2proplus-portable.7z`（2.31 GiB） |
| SHA256 | `ad6f963906a737bfb24b476244476a6407ac21a67298eb0bc6003556d03467e2` |

> 2 GB 以上文件用浏览器可能被要求安装/打开夸克客户端，属正常。

脚本会把模型接到 `models\tts\kurisu-v2proplus`（默认用目录联接，跨盘自动改为复制），并检查 `manifest.json`。

`shared\`（1.0 GiB 公共权重）**不在 Hugging Face 仓库里**，用 AnifLive 自带脚本从上游下载：

```powershell
cd C:\AnifLive-TTS
.\.venv\Scripts\python.exe scripts\setup_shared_assets.py `
  --output D:\QQBot\models\tts\shared `
  --accept-third-party-licenses
```

也可以直接从作者本机的 `D:\models\shared` 复制/联接过去。

`shared` 目录：默认找模型目录上一级的 `shared`（即 `models\tts\shared`）。如果你把它放在别处，在 `deploy\config.psd1` 里设 `TtsSharedDir`。

### 2.5 启用

编辑 `deploy\config.psd1`：

```powershell
TtsEnabled   = $true
TtsExe       = 'C:\AnifLive-TTS\.venv\Scripts\aniflive-tts.exe'
TtsModelDir  = 'models\tts\kurisu-v2proplus'
TtsSharedDir = ''          # 留空 = 模型目录上一级\shared
TtsPort      = 9882
```

启动：

```powershell
.\deploy\start-tts.ps1
# 或 start-all.ps1（会按顺序带起）
```

验证：

```powershell
Invoke-RestMethod http://127.0.0.1:9882/v1/models
```

首次加载模型要 30~120 秒，`start-tts.ps1` 最多等 180 秒。

### 2.6 接到 AstrBot

`ja_voice` 插件配置（`astrbot\data\config\astrbot_plugin_ja_voice_config.json`）：

```json
{
  "enable": true,
  "tts_base": "http://127.0.0.1:9882/v1",
  "model": "kurisu-v2proplus",
  "voice_profile": "default",
  "language": "ja",
  "probability": 1.0,
  "keep_text": true
}
```

- `language: ja`：先把中文翻成日语再合成（音色更像角色）；想直接读中文改 `zh`。
- `probability: 1.0`：每条都发语音。嫌慢/吵就调低到 0.3。
- AstrBot 自带的 `provider_tts_settings.enable` 必须保持 `false`，否则会双发。

重启 AstrBot 后，私聊发一句话，应收到「文字 + 语音」。

### 2.7 性能参考

只有 TensorRT 后端，性能取决于显卡与引擎是否匹配：

| 硬件 | 首包 | 说明 |
|---|---|---|
| RTX 2080 Ti 22G | ~0.5 s | 本项目原机器的数据 |
| RTX 3060 12G | ~1 s | 够用 |
| 无 NVIDIA 显卡 | — | **跑不了**，TensorRT 后端要求 NVIDIA GPU |

显存至少 6 GB 空闲（构建引擎时 workspace 默认 4 GB）；换显卡/驱动/CUDA/TensorRT 版本后都要
`aniflive-tts model rebuild-engines` 重建。

### 2.8 不需要语音时

1. `deploy\config.psd1` 里 `TtsEnabled = $false`；
2. `astrbot_plugin_ja_voice_config.json` 里 `"enable": false`；
3. 删掉 `models\tts\` 省 6.9 GiB（或保留联接）。

`start-all.ps1` 会跳过 TTS，其他功能不受影响。

### 2.9 常见问题

| 现象 | 处理 |
|---|---|
| `start-tts.ps1` 报找不到 exe | `TtsExe` 路径不对；先 `uv run aniflive-tts --help` 确认 |
| 9882 端口起来了但合成 500 | 看 `logs\tts.err.log`；多半是 `shared` 路径不对或引擎与显卡不匹配 |
| 报 `missing TensorRT engines` | 换机器后没重建：`aniflive-tts model rebuild-engines --model-package <目录>` |
| 发语音没反应 | `ja_voice.enable` 是否为 true；AstrBot 是否重启；`:9882` 是否在跑 |
| 语音是日语但语气怪 | `language` 改 `zh` 试试；或调 `voice_profile` |
| 每条都超时 | 显卡太弱或引擎没匹配；把 `probability` 降到 0.2 |
| 想换成自己的音色 | 用 AnifLive 的 `convert` 子命令从 GPT/SoVITS checkpoint 生成模型包，见上游 `docs` |

## 3. 压缩、分享与硬件绑定（实测）

### 3.1 结论：能压，但省不了多少

神经网络权重熵很高，zip/7z 对 ONNX 的压缩率通常只有 **90%~95%**；TensorRT 引擎稍微好一点，
但整包也只能压到 75% 左右。本机实测：

| 对象 | 原始 | 压缩后 | 压缩率 |
|---|---|---|---|
| 单个 `sovits.onnx`（zip/deflate Optimal） | 161.3 MB | 149.4 MB | **92.6%** |
| 整个模型包（含 engines，zip） | 6.86 GiB | 5.14 GiB | **约 75%** |
| 便携包（onnx + voices，7z） | 2.02 GiB | 约 1.9 GiB | 约 92% |
| 便携包 + shared（本地备份，7z） | 3.02 GiB | 2.31 GiB | **约 77%** |

也就是说，**完整包压完仍有 5 GB 左右**；只发模型本体约 2 GiB，加 shared 约 2.3 GiB。都不会小到能塞进 Git 仓库。

### 3.2 真正能省的是「重复的引擎」

| 组成 | 大小 | 说明 |
|---|---|---|
| `onnx\` | 1.99 GiB | 构建引擎的原料，**跨机器可复用** |
| `engines\` | 4.86 GiB | 两套 TensorRT 引擎，各约 2.08 GiB；其中只有 `manifest.json` 里 `active_engine_fingerprint` 那套在用 |
| `voices\` + 元数据 | < 10 MB | 音色配置 |
| `shared\`（模型目录外） | 1.02 GiB | BERT/SSL 公共权重；可用 AnifLive 的 `setup_shared_assets.py` 从上游下载，不必随包分发 |

两套引擎里有一套是旧指纹，可以直接删掉，**省 2.08 GiB**（6.9 → 4.8 GiB）。

但更关键的是：**TensorRT 引擎和硬件绑定**。指纹里包含
`GPU 型号 / 显存 / SM 数 / compute capability / CUDA / TensorRT / 平台`，
换一台机器基本一定不匹配，`AnifLive` 会报 `missing TensorRT engines`。
所以把 engines 发给别人，对绝大多数人**没有用**，对方仍要重建。

### 3.3 推荐分享的「便携包」

给别人的包只放可复用的部分：

```text
kurisu-v2proplus-portable\
├─ manifest.json / source.json / checksums.json
├─ onnx\                1.99 GiB
├─ voices\              < 10 MB
└─ （可选）../shared\    1.02 GiB，用 AnifLive 的 setup_shared_assets.py 下载
```

模型本体约 **2.0 GiB**；加 shared 约 **3.0 GiB**（7z 实测 2.31 GiB）。对方解压后先重建引擎：

```powershell
aniflive-tts model rebuild-engines --model-package <模型目录>
```

> 前提：对方有 NVIDIA 显卡 + CUDA + TensorRT 11。重建会重写 `manifest.json` 和 `checksums.json`。
> 删掉 engines 后原 `checksums.json` 会与目录不一致，这是正常的；重建后会自动修复。
> 只拿这个包、不重建就 `serve`，会报 `missing TensorRT engines`。

本仓库带了一个脚本自动完成上面所有步骤（复制、删指纹、重算 checksums、可选压缩）：

```powershell
# 只生成目录（含 shared，适合本地备份）
.\scripts\build-tts-portable.ps1 -Source "D:\models\kurisu-v2proplus"

# 只打模型本体（约 2.0 GiB，shared 用上游脚本另下）
.\scripts\build-tts-portable.ps1 -Source "D:\models\kurisu-v2proplus" -NoShared -Compress

# 整包 + 分卷（方便网盘或离线拷贝）
.\scripts\build-tts-portable.ps1 -Source "D:\models\kurisu-v2proplus" -Compress -SplitSize 1900m
```

默认输出 `D:\models\portable\`；`-NoShared` 时只包含 `kurisu-v2proplus\`。

### 3.4 模型怎么获取

当前模型放在夸克网盘（2.31 GiB，含 `onnx` + `voices` + `shared`）：

```text
链接：https://pan.quark.cn/s/32fa2c35348a?pwd=RF3D
提取码：RF3D
文件：kurisu-v2proplus-portable.7z
SHA256：ad6f963906a737bfb24b476244476a6407ac21a67298eb0bc6003556d03467e2
```

也可以：

- 从本机已有目录直接接入：`-Source "D:\models\kurisu-v2proplus"`；
- 有直链时：`-DownloadUrl "https://.../kurisu-v2proplus-portable.7z"`。

> 2 GB 以上文件用浏览器可能被要求安装/打开夸克客户端，属正常。
> 模型不要放进本仓库：单文件 100 MB 上限，放不下。

### 3.5 压缩参数建议

- 格式：`7z`（LZMA2）体积最小；`zip` 兼容性最好（Windows 自带解压）。
- 7z 用 `-mx=5` 即可，`-mx=9` 对权重提升很小但慢一倍。
- 大包不要开 solid（`-ms=off`），否则解压要整包读入、耗时且吃内存。
- 需要分卷时：`-SplitSize 1900m`，得到 `.001/.002`；把分卷放同一目录，`-Source` 指向 `.001` 即可。
- 压缩不会改变文件内容，解压后 `-Verify` 的哈希仍然有效。

### 3.6 本仓库脚本怎么用

```powershell
# 从 Hugging Face 下载（推荐）
.\scripts\install-tts-model.ps1 -HfRepo kuris1213/kurisu-v2proplus

# 本地压缩包（.zip / .7z / 分卷 .001）
.\scripts\install-tts-model.ps1 -Source "D:\downloads\kurisu-v2proplus-portable.7z"

# 直链（只支持能直接下载的 URL，网盘分享页不行）
.\scripts\install-tts-model.ps1 -DownloadUrl "https://example.com/kurisu-v2proplus-portable.7z"

# 校验（精简包会提示「另有 N 个文件不在当前包中」，不是错误）
.\scripts\install-tts-model.ps1 -Source "D:\kurisu-v2proplus" -Verify
```

## 4. 磁盘规划

| 项 | 大小 |
|---|---|
| 仓库（含表情包 + bge） | ~280 MB |
| AstrBot 与 Python 依赖 | ~600 MB |
| `.venv-embedding`（torch CPU） | ~2 GB |
| 语音模型（完整，含两套引擎） | 6.9 GiB |
| 语音模型（便携包，无引擎、无 shared） | 2.0 GiB |
| `shared` 公共权重 | 1.0 GiB |
| 重建后的单套引擎 | ~2 GiB |
| 日志与缓存 | 每月几十 MB～几百 MB |

最低 5 GB（不含语音）；含语音建议 10 GB（模型 2 GiB + shared 1 GiB + 本地重建引擎 2 GiB + 临时空间）。
